# Discovery baseline for native Elsa 3 compensation

Evidence date: 19 October 2026. Current main inspected at `df0697fd84e8036db71b6f5740e5df23c7eb517e`. The initial attached checkout was older (`806852c774533c6b26f0ba30b30b507e11f8b15d`) and used obsolete `src/studio/` paths. Planning and the documentation branch use current main's `core/`, `studio/`, `extensions/` and `docs/` layout. Refresh before design execution; source findings are not released-package support claims.

## Elsa 2 historical implementation

The appropriate historical branch is `2.x`, inspected at `7a317f81a7178e13795ace6fbc481724e0415df4` (tag `2.17.0`). The key compensation implementation blobs match release `2.13.0`, commit `f9be19a6102618311bbb35f9b6cee41c84afdd63`, which the regression discussion confirms working. These sources are historical observations, not chosen Elsa 3 contracts.

| Source | Observed behavior | Consequence for design |
|---|---|---|

- [Studio contribution rules](https://github.com/elsa-workflows/elsa-core/blob/df0697fd84e8036db71b6f5740e5df23c7eb517e/studio/src/AGENTS.md) require capability-aware APIs, backend/environment reset, cancellation-aware lifecycle, supported Server/WebAssembly boundaries and explicit unavailable/unauthorized/disconnected states. M0 interaction review must include these, keyboard/screen-reader navigation and non-color state labels.

## Tenant, authorization and sensitive data

[Instance Get](https://github.com/elsa-workflows/elsa-core/blob/df0697fd84e8036db71b6f5740e5df23c7eb517e/core/src/modules/Elsa.Workflows.Api/Endpoints/WorkflowInstances/Get/Endpoint.cs) and [Cancel](https://github.com/elsa-workflows/elsa-core/blob/df0697fd84e8036db71b6f5740e5df23c7eb517e/core/src/modules/Elsa.Workflows.Api/Endpoints/WorkflowInstances/Cancel/Endpoint.cs) illustrate permission-gated operations. Existing tenant-scoped stores and outbox tenant restoration are constraints to preserve, not proof that a future recovery API is isolated.

[WorkflowState](https://github.com/elsa-workflows/elsa-core/blob/df0697fd84e8036db71b6f5740e5df23c7eb517e/core/src/modules/Elsa.Workflows.Core/State/WorkflowState.cs) and context dictionaries hold generic outputs/properties; JSON serialization and storage compression do not establish per-field protection. Studio execution details filter some internal keys but display values and outputs; no compensation disclosure policy exists there. Do not place raw captured credentials or unrestricted participant payloads in broadly returned state/log DTOs. Design safe summaries, authorized protected details, redacted audit/live events and retention that keeps unresolved obligations recoverable. Baseline security is required at M1, not postponed until operator controls.
