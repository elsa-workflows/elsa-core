## Additional integration hazards found in review

- [Workflow-state serializer](https://github.com/elsa-workflows/elsa-core/blob/df0697fd84e8036db71b6f5740e5df23c7eb517e/core/src/modules/Elsa.Workflows.Core/Serialization/Serializers/JsonWorkflowStateSerializer.cs) and [polymorphic converter](https://github.com/elsa-workflows/elsa-core/blob/df0697fd84e8036db71b6f5740e5df23c7eb517e/core/src/modules/Elsa.Workflows.Core/Serialization/Converters/PolymorphicObjectConverter.cs): an unaliased object can return as a property bag. Select an explicit versioned map codec and prove its round trip instead of relying on CLR type identity.
- [State extractor](https://github.com/elsa-workflows/elsa-core/blob/df0697fd84e8036db71b6f5740e5df23c7eb517e/core/src/modules/Elsa.Workflows.Core/Services/WorkflowStateExtractor.cs) skips unresolved scheduled nodes/callback references. Recovery restore admission must detect and preserve blocked obligations before that omission.
- [Publish endpoint](https://github.com/elsa-workflows/elsa-core/blob/df0697fd84e8036db71b6f5740e5df23c7eb517e/core/src/modules/Elsa.Workflows.Api/Endpoints/WorkflowDefinitions/Post/Endpoint.cs) flattens validation errors to messages; [Studio ValidationError](https://github.com/elsa-workflows/elsa-core/blob/df0697fd84e8036db71b6f5740e5df23c7eb517e/studio/src/modules/Elsa.Studio.Workflows.Core/Domain/Models/ValidationError.cs) is message-only. Add a compatible per-diagnostic target contract rather than assuming it exists.
- [Input descriptor](https://github.com/elsa-workflows/elsa-core/blob/df0697fd84e8036db71b6f5740e5df23c7eb517e/core/src/clients/Elsa.Api.Client/Resources/ActivityDescriptors/Models/InputDescriptor.cs) has IsSensitive; [output descriptor](https://github.com/elsa-workflows/elsa-core/blob/df0697fd84e8036db71b6f5740e5df23c7eb517e/core/src/clients/Elsa.Api.Client/Resources/ActivityDescriptors/Models/OutputDescriptor.cs) does not provide an equivalent guarantee. [Execution-by-ID](https://github.com/elsa-workflows/elsa-core/blob/df0697fd84e8036db71b6f5740e5df23c7eb517e/core/src/modules/Elsa.Workflows.Api/Endpoints/ActivityExecutions/Get/Endpoint.cs) returns the record, and ordinary Studio details display outputs. Protected journal storage alone cannot prevent source values from entering those records; require source suppression/redaction and protected drill-down.

## Elsa 4 intent versus reusable proof

The [reviewed semantics](https://github.com/elsa-workflows/elsa-foundation/blob/cc14626050a572acb0bbe4672e0fb35e7f4d0286/specs/250-native-compensation/contracts/semantics.md) and [Studio contract](https://github.com/elsa-workflows/elsa-foundation/blob/cc14626050a572acb0bbe4672e0fb35e7f4d0286/specs/250-native-compensation/contracts/studio-interaction.md) establish paired operations, reverse durable completion ordering, separate outcomes, confirmation and intervention intent. The [data model](https://github.com/elsa-workflows/elsa-foundation/blob/cc14626050a572acb0bbe4672e0fb35e7f4d0286/specs/250-native-compensation/data-model.md) uses active structural private state and committed causal execution data. Elsa 3 has different lifetime/result resolution and must capture values explicitly.

The [later semantics](https://github.com/elsa-workflows/elsa-foundation/blob/e9a3d18aa25ab30e57e6c6a1afdf6dc7fb63fdc0/specs/250-native-compensation/contracts/semantics.md) clarify operation keys and intervention, while still recording late-compensation and cancellation boundaries. M1's runtime-specific Durable/Balanced/Ephemeral and External/ReplaySafe claims do not transfer. Do not defer Elsa 3's mandatory safety checks because a reference warning was assigned to a later milestone. Source design/review and controlled participant tests are distinct from Elsa 3 qualification.

PR #3080 received substantive comment/revision review and merged; its GitHub reviews do not include a formal APPROVED review on its final head. This packet treats it as a reviewed product reference, not independent approval of the Elsa 3 architecture.

## 21 October source revalidation for E1/E3

The [E1/E2 source audit](https://github.com/elsa-workflows/elsa-core/issues/8896#issuecomment-6302821373) and [E3 source audit](https://github.com/elsa-workflows/elsa-core/issues/8896#issuecomment-6302975534) pin source at `a9c5d310dd88d62fc17490b33c030effc9b18cf2`. The lead re-read the material paths. Instance Version is a definition version, not a write fence; EF outer state loading can catch decode failure before journal admission. Persistence/V8a now explicitly require retaining original bytes and preventing fallback resume or an empty replacement. A valid unknown inner journal schema is a separate negative case.

Claimed native faults clear the live exception/incident, while activity-context state does not persist that Exception. E1/E3 must establish a protected original-cause representation and correct native handoff/teardown bookkeeping across restart. Studio's default resolver does not traverse non-activity paired-row objects; property descriptors provide names/types rather than opaque property IDs; the StateMachine diagnostic precedent routes mutable labels. E3 therefore proves explicit StepId/role child traversal, reviewed descriptor binding identity and stable StepId/MappingId navigation after rename/reorder. None of these observations is runtime/browser proof or a frozen public contract.
