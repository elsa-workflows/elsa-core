# Browser resource entity observation

The package journey compares the response entity actually delivered to Chromium with the verified package and generated-resource inventory. These are bytes after HTTP content decoding, not compressed or chunk-framed transport bytes.

Playwright's normal Chromium response-body path may receive decoded text from the Network domain and encode that text as UTF-8. That cannot establish original entity bytes for a text resource containing a byte-order mark. The published 3.8.4 localization script contains a UTF-8 BOM; the earlier hosted receipt reported a size mismatch but did not record the returned size, so the exact cause of that particular failure remains unconfirmed.

The fixture therefore uses a dedicated CDP session and response-stage Fetch patterns limited to the expected Studio asset URLs. It reads the paused original response through `Fetch.getResponseBody`, validates its base64 representation, size, digest, status and media type, and calls `Fetch.continueResponse` with only the request ID. It does not refetch, fulfill, replace or normalize the response. Backend and embedding traffic retain their separate native Playwright observers.

Chromium's [BodyReader implementation](https://chromium.googlesource.com/chromium/src/+/lkgr/content/browser/devtools/devtools_url_loader_interceptor.cc) collects response data-pipe bytes and base64-encodes them. Its continuation path sends that captured body with the original metadata. [FetchHandler](https://chromium.googlesource.com/chromium/src/+/8b96632ef93385dbf3039bb44b9447240102dbd9/content/browser/devtools/protocol/fetch_handler.cc) uses empty modifications when `continueResponse` has no overrides. This is response observation with a pause; it is not a timing or performance measurement.

Browser caching is disabled before navigation so a bodyless 304 cannot substitute for entity evidence. Service workers are blocked by the existing isolated browser context. The observer fails closed on missing bodies, unsupported protocol operations, mismatched bytes, continuation failures and incomplete cleanup. It never reconstructs a BOM or treats a separate HTTP request as native browser evidence. Only path hashes and fixed failure categories leave the private process; successful records retain the existing allowlisted resource metadata.

The observer limits active reads to 128, reserves at most 128 MiB of expected entity bytes, and allows at most 2,048 captured responses and 512 pending protocol operations. These limits bound expected work and retained metadata. CDP still accumulates the actual response before returning its base64 body, so a mismatched oversized response can allocate memory before the observer detects it. This is an observer for verified assets served by the fixture's owned loopback hosts, not a general-purpose bounded downloader for untrusted servers. Missing Content-Length remains supported because the WASM development server can stream valid assets without it.

Fake-CDP contracts check byte preservation and lifecycle failures. They do not certify the browser protocol implementation. The hosted journey with the pinned Playwright/Chromium version must also pass; older browser and tooling runs are not evidence for a changed observer.
