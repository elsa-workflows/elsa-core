# React Studio Preview for 3.11.0

Release preparation for [#8859](https://github.com/elsa-workflows/elsa-core/issues/8859).
These notes describe the opt-in Preview candidate; they do not announce publication.

React Studio adds a Vite/React interface alongside the existing Blazor Studio.
Blazor remains the default throughout Elsa 3.x. The interface, package descriptions,
package tags and README retain the **Preview** label even when the NuGet version
is the plain release number `3.11.0`.

The 18 `Elsa.ReactStudio.*` libraries ship in lockstep with the root package build:
the aggregate, shared host and 16 independently enabled feature libraries. They
target .NET 8, 9 and 10 and embed their built frontend assets. NUKE builds JavaScript
before compiling or packing; deployed hosts require no Node runtime. The standalone
application and test project are excluded from NuGet packing.

The package workflow's existing 3.10 release stream is preserved. React libraries
are excluded when the requested package version is below 3.11.0, including 3.10
proof builds. A 3.11 preview version or plain 3.11.0 includes them automatically.
The existing publication selection checks and publisher approval gates still apply.

The Preview includes workflow authoring and instance inspection, specialized activity
editors, activity settings and retry history. Optional features include security,
secrets, labels, environments, human tasks, alterations, appearance and diagnostics.
Third-party modules use the public SDK and shared UI/auth/API packages; the
[authoring guide](../../react/docs/module-authoring.md) includes a generated,
independently packaged sample.

Follow [Try the React Studio Preview](../try-react-studio-preview.md) for source
and hosted-package instructions. Check the [parity audit](../../react/docs/parity.md)
and [delivery plan](../specs/react-studio-preview/plan.md) for current limits and
remaining acceptance work. Registry and container publication, independent review
and final source cutover are separate delivery gates.
