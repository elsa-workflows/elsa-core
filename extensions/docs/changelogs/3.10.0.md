# Elsa 3.10.0 — Extensions notes

## Persistence (Dapper)

- Dapper `Store<T>` upserts are scoped to the current tenant. A save whose Id already belongs to another concrete tenant throws instead of overwriting that row. An existing tenant-agnostic (`*`) row keeps the previous overwrite-and-restamp behaviour until the rest of [#9010](https://github.com/elsa-workflows/elsa-core/issues/9010) lands.
- **SQLite hosts must use SQLite 3.24 or later.** The Dapper provider now emits `INSERT … ON CONFLICT DO UPDATE` (UPSERT) instead of `INSERT OR REPLACE`. Microsoft.Data.Sqlite with the bundled e_sqlite3 engine already meets this. A host that swaps in an older system SQLite library will fail on save.
