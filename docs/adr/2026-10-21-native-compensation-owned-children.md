# Use native owned children for compensation scopes

Status: Proposed. This ADR records the E3 design for [#8953](https://github.com/elsa-workflows/elsa-core/issues/8953). The source observations are pinned to [`7ca753ccc212cfcffe3e6cf3dd8e01090e9bcd6f`](https://github.com/elsa-workflows/elsa-core/commit/7ca753ccc212cfcffe3e6cf3dd8e01090e9bcd6f). It does not qualify implementation, persistence, security, or Studio behavior.

## Context

The accepted compensation policy requires paired forward and handler activities with durable logical identity across repeated executions. Elsa Core already serializes nested activities in public activity properties and exposes `StateMachine` children through a hidden `IEnumerable<IActivity>` projection for native graph traversal. Studio separately resolves embedded child JSON and selects custom designers. These extension points do not currently provide compensation rows, stable step/mapping identity, strict pre-converter pins, safe recovery capture or occurrence inspection.

## Proposed decision

Implement the first native scope in Elsa Workflows Core as an activity that owns versioned serialized step rows. A row owns its forward and inline handler `IActivity` children and stable logical StepId/MappingIds. A hidden non-serialized activity projection exposes those owned child objects to Core traversal, following the StateMachine pattern. Studio adds a Workflows.Core JSON resolver for row-owned children and a custom Workflows diagram designer for paired authoring; graph ports remain data/control-flow mechanisms, not the paired editor.

The protected M1 profile is narrow: exact root definition-version provenance, exact child activity type/version pins, inline handlers only, direct compatible capture mappings and compatible authored handler literals. Its candidate participant/profile allowlist remains empty until E1/E2 qualify a real entry and source-suppression boundary; the [pinned E2 recovery-data contract](https://github.com/elsa-workflows/elsa-core/blob/60aa5933f08ff14ba0332d05e2acb13d53003ca4/core/docs/specs/native-compensation/recovery-data.md) owns capture protection and disclosure policy. Publish refusal must be mandatory even when global validation errors are configured not to fail, and must precede publication notification and state mutation. `WorkflowDefinitionActivity` handlers and unversioned converter-backed mappings are unsupported. Preserve ordinary Elsa 3 fallback behavior.

Protected strict-pin validation should use a narrow recognized-scope branch in `ActivityJsonConverter.Read` to inspect original owned-child `type`/`version` tokens before descriptor fallback. `ActivityConstructorContext` exposes no raw JSON. If the full protected scope cannot be resolved, preserve it as `NotFoundActivity.OriginalActivityJson` for a read-only draft and reject publish/activation. Prove this path on both current Save + Publish and stored workflow materialization; the POST model's `Root:IActivity` and later semantic validation do not establish that raw pins survive today. Preserve ordinary 3.x fallback. Keep the exact request DTO/route spelling open until the actual Core/Management caller is implemented and reviewed. The declared recovery schema must explicitly define required/optional, omission/default and nullable/explicit-null semantics because current input descriptors do not expose those contracts.

Recovery inspection consumes the E2-safe, paged instance summary → scope activation → distinct forward occurrence → direction-tagged attempt → exact execution caller. Preserve the causal link from the forward execution to its recovery attempt, including repeated activations of one StepId. It must not depend on the current generic full-instance GET or latest execution by diagram node. Definition labels/layout require separate definition-resource authorization. Exact public DTO, endpoint and permission names remain open; M4 mutation UI is outside this decision.

## Consequences and proof still required

The activity graph, serialized ownership and Studio JSON tree need explicit symmetric tests. Save/reopen must preserve StepId/MappingIds and incomplete/unknown drafts. Runtime must associate each scheduled child callback with its scope activation, forward occurrence, direction/key/attempt and exact execution without treating Activity.Id, NodeId or arbitrary Tag as durable operation identity. Test absent versus explicit null using a declared schema rather than inferring from `Nullable<T>`. The mandatory compensation publish gate must prove refusal under `FailOnValidationErrors = false` through both Save + Publish and stored Publish, with no prior-version mutation. E1/E2/E3 must qualify strict pins, persisted restore, actual participant source suppression before generic log/incident/mapping copies, trusted-tenant authorization, protected projection, both O3 handoffs and the real Studio host. Restart proof requires an abrupt backend kill, positive old-process-stopped evidence, the same database and keys, a new backend process and Studio reconnect; graceful flush is insufficient. Until those proofs pass, the decision remains Proposed and M1 remains Not Ready.

Reusable workflow-as-activity handlers may be reconsidered at M3, or earlier for a concrete caller after strict definition-version selection and restore are proved. Converted mappings may be reconsidered when an immutable versioned recovery-converter identity and execution path exist. Unsupported profiles fail closed before effect; they do not change ordinary Elsa 3 workflows.

See the canonical [E3 caller contract](../../core/docs/specs/native-compensation/e3-studio-contract.md) and [native compensation packet](../../core/docs/specs/native-compensation/README.md).
