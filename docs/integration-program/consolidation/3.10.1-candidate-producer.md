# 3.10.1 unpublished candidate producer

This is a no-publication pack path. It does not authorize NuGet.org or Feedz
push, tagging, or reuse of the staged 3.10.0 pin.

## Split

| PR | Role |
| --- | --- |
| #9193 | Advisory pins and MySQL net8/net9 matrix. Head `561f652404076ee827ab93ac3700a8033b9529fc` is the CR-requested pin source. |
| #9195 | Publication selection guard only. Head `d8f6de57270431c807449f2f2b30c322148330f9`. Rejects nuget.org for stable 3.10.x until a distinct later pin exists. |
| This producer | `prepare-consolidated-3.10.1-release-candidate.yml`. Packs **3.10.1** from an explicit source SHA after #9193 is in that SHA. Does not retarget the 3.10.0 producer or Feedz executor. |

Do not squash this producer into #9195. Do not retarget
`publish-consolidated-original-candidate.yml` or edit
`stable-original-envelope.json` / `consolidated-pin-inventory-baseline.json`.

## What it produces

An unpublished GitHub Actions artifact named
`consolidated-candidate-<source>-<run>-<attempt>` with:

- package version **3.10.1** (nupkg names, seal, envelope)
- the 231-ID inventory guard (`validate_packages_id_set.py` plus the candidate baseline)
- a new artifact ID / run / digest (not `12664519771` / `40347931480` / `5cff67228`)
- `published: false`

The original 3.10.0 private-fix provenance stays in git history on
`release/3.10.0`. This workflow packs the requested HEAD; it does not rewrite
that history or regenerate 3.10.0 signed claims.

## Exact dispatch (after #9193 is merged into the chosen ref)

No 3.10.1 tag is required. Do **not** run this until parent confirms gates.
Do **not** treat a green producer run as publication approval.

```bash
git fetch origin release/3.10.0
SHA=$(git rev-parse origin/release/3.10.0)
# SHA must contain the reviewed #9193 pins (MySqlConnector 2.6.2 and
# SQLitePCLRaw.lib.e_sqlite3 2.1.14). It must not be 5cff67228.
gh workflow run prepare-consolidated-3.10.1-release-candidate.yml \
  --ref release/3.10.0 \
  -f version=3.10.1 \
  -f source_commit="$SHA"
```

`--ref` selects the workflow file and the packed tree. `source_commit` must
equal that run’s `github.sha`. A mismatch, the 3.10.0 pin SHA, or a tree
without the advisory pins fails before pack.

## Remaining pin / publication flow (later reviewed PRs)

1. Producer run succeeds; record the new artifact ID, run ID, attempt, source SHA, archive digest, envelope.
2. Independent QA on those new bytes: snupkg archive, live MySQL on net8/net9, image QA. Combined net10 MySQL is unsupported.
3. Reviewed pin module for **3.10.1 only** (new `PRODUCER` identity). Do not edit the 3.10.0 envelope or default the old artifact.
4. Selection change so `packages.yml` `publish_nuget` accepts only `refs/tags/3.10.1` against that new pin.
5. Actual signoff, then tag/publish. #9195 keeps 3.10.0 nuget.org rejected.

Until step 4 exists, these stay rejected:

```text
gh workflow run packages.yml --ref 3.10.0 -f publish_nuget=true
gh workflow run packages.yml --ref 3.10.1 -f publish_nuget=true
gh workflow run publish-consolidated-original-candidate.yml -f operation=publish
```
