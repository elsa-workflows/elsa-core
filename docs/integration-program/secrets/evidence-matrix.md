## External provider examples that shape policy

These official provider docs illustrate why Elsa must store a provider policy rather than assume every OAuth token is a short-lived cache entry:

- [Moneybird authentication](https://developer.moneybird.com/authentication/) says current access tokens do not expire, advises storing both access and refresh tokens, and documents `/oauth/revoke` as revoking the paired tokens when either is revoked. A provider can change its token lifetime later, so read expiry metadata when supplied.
- [Slack token rotation](https://docs.slack.dev/authentication/using-token-rotation/) describes opt-in rotation that cannot be disabled after enablement, 12-hour access tokens, single-use refresh tokens with a short grace period, and a two-active-token limit. `auth.revoke` and uninstalling an app installation have different scope.

These are examples only. This evidence does not claim Elsa has a Moneybird or Slack connector, or implements their refresh/revoke operations. Each adapter must pin its provider's current docs and define retry, expiry, and uninstall semantics.
