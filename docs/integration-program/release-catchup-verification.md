## Bounded save retry follow-up

Final review identified an availability edge case under repeated same-tenant delete/reinsert churn. [Extensions #287](https://github.com/elsa-workflows/elsa-extensions/pull/287) at `a24de2986e0a02c335bdd3f86e47bd049949d3b4` and mapped Core `6e7f73942dc2b820470661e9d5b016bf8dc8ee4a` cap owned-update retries at five attempts, then throw a descriptive concurrency exception. They preserve scoped Value-only writes and never report an unapplied value as saved. Cancellation retains priority.

A deterministic real SQLite/PostgreSQL delete/reinsert regression failed on both providers before the fix, bounded by a distinct test safety exception without cancellation or background operations. Afterward, all 28 ownership cases passed; the complete source persistence suite passed 100/100 and Core passed 132/132, with zero failures/skips. Independent review verified the implementation and raw TRX. The source receipt still accounts for all 48 paths, now pinned through this follow-up.
