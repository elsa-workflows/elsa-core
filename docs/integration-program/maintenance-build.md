## Run a nonpublishing proof

Use a reviewed, clean Core checkout with all history and SDKs 8/9/10, Node 22 and Python 3.12 on an isolated hosted runner. All four source commits are ancestors of the reviewed Core baseline `8802a883d6`; `fetch-depth: 0` obtains them without source repository fetches or new remote refs. The controller rejects missing objects, changed parent/tree/workflow inventories and unregistered selections. Source checkout uses a local Git fetch without tags or credentials and sets the original public repository URL solely for truthful original-source metadata.

```sh
python scripts/integration-program/prepare_maintenance_build.py \
  --product studio --line 3.8 \
  --commit 9bff3f785fd13bd80a3a7ecf88fec4aec8eef7ae \
  --version 3.8.4-proof.12345.1 \
  --output /absolute/new/directory/maintenance-proof
```

The output must be new and outside the controller checkout. Only `MAJOR.MINOR.PATCH-proof.RUN.ATTEMPT` versions on the selected 3.8 or 3.9 line are allowed. Released versions, tags, arbitrary refs, cross-product commits, 3.10 versions and registry/token/command inputs are not accepted. This rehearsal has no version allocation or publisher capability.

The [workflow](../../.github/workflows/prepare-maintenance-build.yml) runs four independent jobs on the temporary reviewed `codex/maintenance-builds-8677` push branch. After registration on main, manual dispatch accepts one explicit product, line, original commit and proof version; dispatch from other refs is skipped. Registration on main is routine nonpublishing verification, not publisher activation. Each job has `contents: read`, `actions: none`, checkout credentials disabled, no OIDC, environment, registry secret or publisher action. Source subprocesses receive a small environment allowlist excluding GitHub/registry credentials and Actions output/authority handles. Historical workflow YAML and composite publisher actions are never invoked. Only Actions evidence artifacts are uploaded.

Studio 3.8 builds both original ClientLibs, then builds, tests and packs `Elsa.Studio.sln`. Studio 3.9 first restores the Designer project and checks generated BPMN types and ClientLib tests before building those assets. Extensions invokes its original `./build.sh Compile+Test+Pack --configuration Release --version VERSION --analyseCode true`. The fixed proof-only `EmbedUntrackedSources=true` MSBuild property is passed explicitly to Studio build/test/pack and through the controlled environment to the original Extensions NUKE recipe. The receipt records this property; source code and dependency pins remain unchanged. Extensions retains its source-configured `--analyseCode true` recipe: pinned NUKE supplies a per-project TRX logger, and the original build writes those results to `source/testresults`. Both products use the same strict actual TRX project/TFM verifier; runnable cells require positive passing results, and only the two source-bound placeholders described below can remain skipped; console `Passed!` summaries do not establish acceptance. There is no CustomElements publish or wasm/react npm packing in this task. Dependency builds required by these recipes are allowed; other products are not silently published.

Explicit `--configuration Release` preserves the original hosted configuration on a local controller, where the pinned NUKE components otherwise default to Debug while archive verification reads Release outputs. The selected Extensions preflight rejects missing, Debug or duplicate configuration arguments before tool/helper/product processes. This does not impersonate CI or change local warning/CI behavior: original compilation remains unversioned, and only original Pack settings receive the requested version. Source-confirmed parameter binding is provided by [Nuke.Components 10.1.0](https://github.com/nuke-build/nuke/blob/8aaec258a7e00e5d98e013be025db1a42bc58d79/source/Nuke.Components/IHazConfiguration.cs); actual child arguments still require native execution evidence. ## Evidence and current completion boundary

Actions records the uploaded archive digest independently. A green workflow flag alone does not establish these checks; read the receipt and retained files. Raw command logs and TRX stay private on the runner and are not uploaded. Receipts contain numeric process exit codes and closed process outcomes, at most 32 compiler/NuGet/MSBuild diagnostic-code counts, exact recognized NUKE failed-target markers, known static verification reason codes (unknown failures stay unknown), expected test project/TFM cells, admitted observed cells and closed unknown/duplicate/positive-summary counts, relative source/project locators and counts; no raw exception text, machine identifiers or absolute runner paths are retained.

The safe base package inventory is retained immediately after evaluation, before test-evidence verification, symbol-helper preparation or SDK metadata staging. Failures in those later stages preserve that base inventory and a failed receipt; successful metadata staging replaces it with enriched public evidence.

Every original product recipe and subsequent SDK inventory, satellite and metadata evaluation receives `RestoreConfigFile` bound to the admitted source's regular `NuGet.Config`. Before invoking tools, the controller compares that file with the exact source Git blob and, when a selected plan is supplied, its feed-config hash. It never inherits an arbitrary `RestoreConfigFile` from the caller. This uses the existing MSBuild restore property to exclude ambient user/ancestor mappings while preserving original recipe arguments, configured feeds, HOME and Core VERSION/provider-gate semantics. No product source or global NuGet settings are changed.

After the original build/test/pack, each evaluated project stages SDK dependency metadata using `_GetRestoreProjectStyle;GenerateNuspec`, the same Release/proof-version/embedding properties, `NoBuild=true` and `ContinuePackingAfterGeneratingNuspec=false`. Package output is forbidden during this stage. Complete main and symbol dependency groups must match their respective SDK-rendered expectations, including third-party ranges, include/exclude metadata and empty framework groups. Main and symbol framework-reference groups must also match their respective SDK-rendered expectations, including empty groups, and target evaluated frameworks. Missing expected metadata fails. The existing same-line Elsa version and main/symbol agreement checks also apply. Retained inventory binds both kinds of expected groups to the staged nuspec hashes, unchanged actual restore-input hashes and resolved SDK/compiler identities. Raw nuspecs and restored assets remain private inside the unretained source checkout; this stage does not rebuild or repack products.

PDB maps must name the original source repository and exact original commit. Tracked document checksums are compared with immutable original Git blobs, not workspace files regenerated during the build; mismatches cannot fall back to embedded content. Non-Git documents require matching embedded bytes plus a known family bound to the admitted original source, evaluated project and TFM, and verified actual resolved SDK, analyzer or restored generator identity. SDK metadata and the canonical Razor, Refit, logging, regex, JSON, resx and PolySharp families use exact project/Release/TFM paths. Physical gRPC and ProtoGrain families use explicit original Extensions project/path bindings; LocalCache grains are admitted only for 3.8. Their embedded bytes are producer-bound, not independently regenerated. Unmapped documents are limited to audited manifest Hints from the exact officially pinned `.50` archive, matching archive-entry and extracted bytes and actual resolved Compile input membership. Unknown paths, families or missing/ambiguous producer evidence fail even when embedded checksums match. Receipts use closed `[embedded]/document-N` locators and allowlisted family/producer identities, hashes and archive entries. Absolute compiler, targeting-pack, package-cache and input paths stay private.

Assembly identity must match evaluated AssemblyName. Only explicitly evaluated IncludeBuildOutput=false permits an assembly-free package. Per-framework SDK SatelliteDllsProjectOutputGroupOutput items supply exact culture-relative satellite paths; their archived bytes must equal the emitted FinalOutputPath bytes and recorded hash. Resource satellites are recorded separately and do not require primary-style external PDBs. Unlisted nested DLLs are rejected. Assembly versions and informational versions are recorded as actually built; consolidated 3.10 assembly assertions are not applied. The real accepted `VerifyPackageSymbolPair` helper verifies the Portable PDB identity and normalized checksum and reports the unchanged PDB hash.

An empty PDB document table is admitted only when real PE inspection validates any present method-body RVAs and reports exact integer zeros for executable bodies, nonabstract bodyless methods and native/external methods, a positive real non-module type count, and a known false reference-assembly flag. Missing, malformed or ambiguous shape evidence fails. External PDB association, identity/checksum, original-commit SourceLink and package checks still run. The receipt records `no-documents-no-executable-method-bodies` applicability and actual counts; this is no source-document coverage claim. Assemblies with any documents retain the full checksum verification, and executable assemblies without documents fail. No package-name exception is used.
