## Native excluded-content markers

SDK-pinned NuGet can replace a nonempty excluded content group with `contentFiles/any/any/_._` (`None`, `any`, `copyToOutput=false`) even when no such ZIP member exists. The selected consumer accounts for that exact external-package sentinel separately from real payload bytes. It requires the same selected-root original snapshot/TFM/package/version/native content hash, exact frozen archive hash and original content inventory; it never borrows another project's context. The original group must either contain the same sentinel or contain real, archive-present content now excluded at the sole selected PackageReference's default transitive boundary. Native restored direct-dependency metadata must retain that sole exact locked root and default asset flags.

The retained marker records an explicit origin and archive hash, with no invented size or file hash. Its judgment is inherited from the source-bound native consumer and private original snapshot (`sdk_restore.original_assets_sha256`); seal readback checks the closed marker schema and restored external archive join, not a fresh NuGet flag computation. Real archive `_._` entries still require ordinary extracted-byte verification. Other missing paths, marker kinds/metadata, selected-package synthetic markers, cache files/symlinks and archive case collisions fail closed.

The pinned SDK source basis is dotnet/dotnet commit `caa81fa4971f74880cdab61990cb1b11420939ec`: [PackagingUtility](https://github.com/dotnet/dotnet/blob/caa81fa4971f74880cdab61990cb1b11420939ec/src/nuget-client/src/NuGet.Core/NuGet.DependencyResolver.Core/PackagingUtility.cs#L14-L40) defaults nuspec dependency assets to `NoContent`; [LockFileUtils](https://github.com/dotnet/dotnet/blob/caa81fa4971f74880cdab61990cb1b11420939ec/src/nuget-client/src/NuGet.Core/NuGet.Commands/RestoreCommand/Utility/LockFileUtils.cs#L943-L948) replaces an excluded nonempty group with [CreateEmptyItem](https://github.com/dotnet/dotnet/blob/caa81fa4971f74880cdab61990cb1b11420939ec/src/nuget-client/src/NuGet.Core/NuGet.Commands/RestoreCommand/ContentFiles/ContentFileUtils.cs#L225-L232). Explicit nuspec includes and merged paths can alter effective flags; this accounting inherits the exact native exclusion judgment and does not independently implement their algebra.

The current native project and its dependency-group projection must contain exactly the default, locked selected root. Every target is a package node; the external package must have exactly one incoming target edge, from that root, matching the exact plan/archive dependency group and explicitly excluding Build. Known include flags cannot undo the exclusion; unknown flags and alternative incoming or direct dependencies fail.

The same-root original raw snapshot must join the exact external package/version/TFM/native content hash and frozen archive. This adapter admits only matching `build/<TFM>` directories and empty properties.
