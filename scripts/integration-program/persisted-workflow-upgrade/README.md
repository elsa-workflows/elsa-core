# Persisted workflow package upgrade proof

This nonpublishing fixture upgrades actual Elsa 3.8.4 and 3.9.0 SQLite workflow state directly to the verified consolidated candidate on the same framework. All six combinations with net8.0, net9.0 and net10.0 must pass. A development `--cell 3.8.4/net8.0` run records `complete_matrix: false` and cannot satisfy the matrix gate.

```sh
python3 -m unittest discover -s scripts/integration-program -p test_persisted_workflow_upgrade_fixture.py
python3 scripts/integration-program/run_persisted_workflow_upgrade_fixture.py \
  --proof-artifacts /absolute/path/to/extracted-original-proof \
  --proof-archive /absolute/path/to/original-proof.zip \
  --output /absolute/path/outside-checkout/new-evidence-directory
```

Install the .NET 8, 9 and 10 SDKs/runtimes and Python 3.10 or later. The output directory must not already exist. Each cell generates standalone PackageReference consumers outside the checkout, with separate initially empty package caches and build directories. Baselines resolve from NuGet.org and require their released nuspec source commits. Candidate packages use exact ID mapping for the complete inventory, verified archive hashes and cache-source/byte checks. Unknown, excluded or wrong-version Elsa dependencies fail. Loaded Elsa assembly hashes must match the selected package runtime assets.

The candidate is fixed to proof run 37410240989, artifact 11390805430, source `44083dc4f47d56aa2d5c215b0c7479c0b7290cb0` and version `3.10.0-proof.37410240989.1`. Its original archive SHA-256 is `8317e5766591f9da2d1f83cd6a85274bd41efbfbd0039d6a1bcfaf0c9bf81636`. It contains 225 package/symbol pairs and 124 project exclusions (123 distinct exclusion IDs). Never rebuild or relabel these bytes. The narrowly path-filtered pull-request/manual `Persisted workflow upgrade proof` workflow checks out the exact head and retrieves/verifies the original artifact. That artifact currently expires on 2026-10-13; expiration fails the lane. An equivalent replacement proof requires an explicit reviewed identity update, rather than silently selecting the latest artifact.

One shared Program.cs is compiled against both releases and the candidate. Three separate processes perform baseline publication/suspension, candidate migration/resumption, and fresh candidate terminal-state verification. The definition uses only built-in Sequence, SetVariable, Event and SetOutput activities, stable identities, null OriginalSource, serializable Input/Variable expressions and explicit string/int/bool input/output metadata. Every input and the input-derived sentinel uses WorkflowInstanceStorageDriver. The candidate resumes the saved BookmarkId without supplying inputs or variables, creating an instance, or republishing a definition.

Typed assertions require exact JSON string, integer and boolean values, alongside the persisted String/Int32/Boolean metadata. The normal payload reader materializes the integer as System.Int64 in both baseline and candidate; receipts record actual CLR types. This proves primitive semantic preservation and declared metadata, without claiming preservation of the original boxed Int32 representation.

Management and runtime use distinct SQLite files and default tenant configuration. Normal tenant startup runs the configured RunMigrationsStartupTask/Database.MigrateAsync path. Receipts retain actual applied/pending histories before and after startup. The provider itself already ignores PendingModelChangesWarning in both baselines and the candidate; this fixture adds no warning override. Migration success still requires completion, empty pending sets and matching independently read SQLite histories. No EnsureCreated, SQL schema repair, synthetic state seeding, state import or query-filter bypass is used. The durable sentinel is stored in the owning root activity context's Properties; after normal completion removes that context, its derived text output proves the successful read.

After clean baseline process exit, fresh read-only SQLite connections check integrity and use SQLite backup to include committed WAL pages. Immutable baseline snapshots precede candidate mutation. Fresh read-only connections corroborate persisted definition/instance/bookmark rows, compression, serialized input, sentinel and output after each phase. API reads reject missing/default state, changed identities/payloads, unexpected incidents and bookmark recreation; deserialization fallback logs fail the proof. Final status/output and bookmark consumption must survive the third process.

The original archive digest binds all extracted inputs; safe extraction rejects traversal and symlinks, and directory verification rejects altered or extra files. Empty local Directory.Build.props/targets and Directory.Packages.props isolate parent imports, and a generated global.json pins the available .NET 10 SDK. Assets corroborate effective restore sources/config and the exact single cache without fallback folders.

The output retains projects, NuGet configs, assets/lock files, package caches, raw process logs, phase/cell receipts, SDK information, both databases and baseline snapshots for local diagnosis. Commands have finite deadlines and process-group cleanup. Failed cells remain failed with their evidence retained.

CI uploads only the explicitly staged retained-evidence directory: public-upgrade-proof.json, the known synthetic management/runtime database files and their WAL files if present, immutable baseline snapshots, and structured execution logs. The retention manifest records every original database byte hash and size. Databases contain only this disposable fixture's generated inputs/definition/state; they are copied without rewriting. SHM, caches, project/config files and arbitrary files are excluded, and symlink/path escapes fail retention.

Hosted execution logs contain command kinds/phases, exit codes/timeouts, recognized diagnostic codes/exception types, raw output digest/size and failed-phase identity. They exclude full commands, machine paths, raw log messages and exception text. Raw process logs and receipts remain local to the runner; the retained structured logs and original synthetic databases allow failure diagnosis without uploading credentials or private paths. No configured credentials, publisher, deployment or source repository changes are involved.
