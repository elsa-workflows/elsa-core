# Accessibility Checklist

- [x] A11Y001 Queue and detail actions are keyboard operable.
- [x] A11Y002 Status, health, priority, and overdue state do not rely on color alone.
- [x] A11Y003 Desktop split view has a route-equivalent narrow/mobile detail experience.
- [x] A11Y004 Loading, empty, error, conflict, and asynchronous accepted states have announced text.
- [x] A11Y005 Forms preserve provider labels, descriptions, validation messages, and focus management.
- [x] A11Y006 Claim/release/complete/reassign controls expose names and disabled reasons.
- [x] A11Y007 Realtime invalidations do not unexpectedly move focus or replace in-progress input.
- [x] A11Y008 Guest verification reveals generic but actionable accessible feedback.
