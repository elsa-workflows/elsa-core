# Elsa 3 Roadmap

Last refreshed 2026-11-25

Elsa gives .NET teams an embeddable workflow engine and visual authoring tools for long-running business processes. The priorities below reflect maintainer work, customer-funded work, and community contributions. Follow the linked milestones and issues for delivery status.

## Current releases

- **3.10.2 is the latest stable release.** It hardens workflow start and resume, tenant and role isolation, workflow authoring, and recovery. Read the provider-specific upgrade notes before rolling it out. [3.10.2 release and upgrade notes](https://github.com/elsa-workflows/elsa-core/releases/tag/3.10.2)
- **Core, Studio, and Extensions ship together from this repository.** 3.10.1 was the first public consolidated release. Apps and Templates also live here. Templates has its own package and release process. Release transfer and retirement of the former source repositories are tracked separately. [3.10.1 release](https://github.com/elsa-workflows/elsa-core/releases/tag/3.10.1) · [Source consolidation](https://github.com/elsa-workflows/elsa-core/issues/8740) · [Release transfer](https://github.com/elsa-workflows/elsa-core/issues/8741)
- **3.11 is in release preparation.** The release includes runtime and multitenancy changes and targets an opt-in React Studio Preview alongside Blazor, the default throughout Elsa 3.x. Track the release and Preview publication through the milestone and linked issues. [3.11 milestone](https://github.com/elsa-workflows/elsa-core/milestone/50) · [Release preparation](https://github.com/elsa-workflows/elsa-core/pull/9283) · [React Studio Preview](https://github.com/elsa-workflows/elsa-core/issues/8859) · [Preview npm publication](https://github.com/elsa-workflows/elsa-core/issues/8858)
- **3.6.4 has a GitHub maintenance release for bookmark queue delivery.** NuGet.org publication recovery is in progress. [3.6.4 release](https://github.com/elsa-workflows/elsa-core/releases/tag/3.6.4) · [Package publication](https://github.com/elsa-workflows/elsa-core/pull/9324)

Elsa 4 follows a separate development program. This roadmap covers Elsa 3. [Generation roadmap](https://github.com/elsa-workflows/elsa-core/issues/8194)

## Capability checklist

`[x]` Released foundation · `[~]` Foundation shipped or merged, with delivery or adoption work ahead · `[ ]` Roadmap candidate

### Production confidence

- [x] **Dispatch and admission.** Built-in exclusive activation strategies shipped in 3.9. The 3.10 line improves outbox delivery and cancellation of waiting child workflows, and tightens duplicate starts and bookmark resumption. Connections and durable event-admission packages first shipped in 3.10.1. [Activation changes](https://github.com/elsa-workflows/elsa-core/pull/8179) · [3.10.1 release](https://github.com/elsa-workflows/elsa-core/releases/tag/3.10.1) · [3.10.2 release](https://github.com/elsa-workflows/elsa-core/releases/tag/3.10.2)
- [~] **Graceful shutdown and recovery.** Pause, resume, drain, and interruption handling are in place. Main adds recurring recovery of interrupted instances. The next work is to verify restart and drain across stores and clustered hosts, cover cases where interrupted activities can be skipped, and show operators what they can safely resume or retry. [Graceful shutdown](https://github.com/elsa-workflows/elsa-core/issues/6401) · [Recovery](https://github.com/elsa-workflows/elsa-core/issues/4833) · [Recurring restart](https://github.com/elsa-workflows/elsa-core/pull/9167) · [Interrupted activity case](https://github.com/elsa-workflows/elsa-core/issues/8467)
- [~] **Distributed runtimes, schedulers, and queues.** Build on the existing MassTransit, Quartz, Hangfire, Kafka, Azure Service Bus, and Proto.Actor integrations. Prioritize tenant-aware scheduling and queue delivery through duplicate messages, retries, and rolling upgrades. [Quartz tenant scope](https://github.com/elsa-workflows/elsa-core/pull/9121) · [Queue delivery on the 3.11 branch](https://github.com/elsa-workflows/elsa-core/pull/9323) · [Dispatch queue discussion](https://github.com/elsa-workflows/elsa-core/discussions/8551)
- [ ] **Native compensation and saga recovery.** The program has an accepted design, a restart experiment, and an open PR for draft authoring. The goal is to author, run, inspect, and recover compensating workflows in Studio, with durable recovery across restarts and clear handling of uncertain external effects. [Program](https://github.com/elsa-workflows/elsa-core/issues/8884) · [Requirements](https://github.com/elsa-workflows/elsa-core/issues/8886) · [Studio draft authoring](https://github.com/elsa-workflows/elsa-core/pull/8968)
- [ ] **Native background execution.** A workflow-aware execution model and a common runtime contract for actor backends remain design candidates. [Background execution](https://github.com/elsa-workflows/elsa-core/issues/7356) · [Actor runtime readiness](https://github.com/elsa-workflows/elsa-core/issues/7313)

### Authoring and Studio

- [x] **Blazor Studio.** Visual editing, semantic state-machine authoring, custom elements for embedding, and opt-in activity output conversion are available. Follow-on work includes maintained examples and a small converter catalog. [Studio docs](https://github.com/elsa-workflows/elsa-core/tree/main/studio/docs) · [State machine](https://github.com/elsa-workflows/elsa-core/issues/5085) · [Output converters](https://github.com/elsa-workflows/elsa-core/issues/7770)
- [~] **React Studio Preview.** Workflow authoring and instance inspection, expression editors, and a module SDK are in source. Preview priorities are dependable create, edit, publish, run, and inspect flows, with clear parity limits and an embedding path. [Preview guide](https://github.com/elsa-workflows/elsa-core/blob/main/studio/docs/try-react-studio-preview.md) · [Parity audit](https://github.com/elsa-workflows/elsa-core/blob/main/studio/react/docs/parity.md)
- [~] **BPMN authoring and execution.** BPMN runtime and interchange packages first shipped in 3.9. Main adds BPMN creation and XML editing in Blazor Studio, a default bpmn-js modeler, and expanded runtime validation and condition handling. Continue toward a tested support matrix, richer instance inspection, and visual authoring parity across Studio hosts. The X6 and React Flow modelers have their own scope. [BPMN v2](https://github.com/elsa-workflows/elsa-core/issues/8898) · [X6 editor](https://github.com/elsa-workflows/elsa-core/issues/8928) · [React BPMN authoring](https://github.com/elsa-workflows/elsa-core/issues/8929)
- [~] **Human workflows.** User Tasks packages first shipped in 3.9, building on the Studio workbench, task queues, and guest completion. 3.10 adds server support for actions such as approve and reject. Finish Studio action editing and validate task completion, recovery, and persistence across supported providers. [3.9 release](https://github.com/elsa-workflows/elsa-core/releases/tag/3.9.0) · [Studio action editing](https://github.com/elsa-workflows/elsa-core/issues/8763)
- [~] **Workflow organization and authoring ergonomics.** Build on labels, instance paging, and existing editors. Improve search, metadata and folder views, input validation, activity version visibility, and consistent run and dispatch controls. [Organization](https://github.com/elsa-workflows/elsa-core/issues/5872) · [Metadata](https://github.com/elsa-workflows/elsa-core/issues/6307) · [React Studio tracker](https://github.com/elsa-workflows/elsa-core/issues/8859)
- [ ] **Workflow testing and debugging.** Build on the activity testing helpers and execution journal to make whole-workflow tests, failed-step investigation, child-workflow navigation, and progress views easier. ElsaScript remains an experimental authoring path. [Testing guide](https://github.com/elsa-workflows/elsa-core/blob/main/core/docs/qa/test-guidelines.md) · [Workflow progress discussion](https://github.com/elsa-workflows/elsa-core/discussions/6012) · [ElsaScript](https://github.com/elsa-workflows/elsa-core/issues/7055)

### Integrations and ecosystem

- [ ] **Wolverine workflow dispatcher.** Add a Wolverine implementation of Elsa's workflow dispatch contract as an opt-in alternative for applications using Wolverine. Verify dispatch, retries, duplicate delivery, and cancellation before documenting the switch. Elsa currently pins MassTransit, its Azure Service Bus integration, and its RabbitMQ integration to 8.5.7. Evaluate where hosts using Wolverine can omit the MassTransit dependency. The MassTransit v9 package strategy remains an open discussion. [Discord discussion](https://discord.com/channels/814605913783795763/1575065341510287445) · [Package versions](https://github.com/elsa-workflows/elsa-core/blob/be796b65e89a83941af78351582f988ed391d9f4/Directory.Packages.props#L147-L150) · [Dispatch contract](https://github.com/elsa-workflows/elsa-core/blob/main/core/src/modules/Elsa.Workflows.Runtime/Contracts/IWorkflowDispatcher.cs) · [MassTransit v9 discussion](https://github.com/elsa-workflows/elsa-core/discussions/6583)
- [x] **Integration building blocks.** Connections, Secrets, package manifests, and Nuplane-based modular hosting are available. Extensions include messaging and schedulers, SQL and CSV, GitHub, cloud storage, and MQTT, which first shipped in 3.9. [Extensions](https://github.com/elsa-workflows/elsa-core/tree/main/extensions) · [Modular Server](https://github.com/elsa-workflows/elsa-core/tree/main/core/src/apps/Elsa.ModularServer.Web) · [3.9 release](https://github.com/elsa-workflows/elsa-core/releases/tag/3.9.0)
- [ ] **Connector SDK and catalog.** Use shared contracts for tenant-owned connections, credentials, typed actions, retries, and diagnostics. Then use the proposed OneDrive, Moneybird, and Slack work to test those contracts before expanding the catalog. The earlier connector program tracks this work as deferred. Azure DevOps, wider Microsoft 365, and Google Workspace remain candidates. [Connector SDK](https://github.com/elsa-workflows/elsa-core/issues/8199) · [Pilot connectors](https://github.com/elsa-workflows/elsa-core/issues/8202) · [Catalog](https://github.com/elsa-workflows/elsa-core/issues/8203) · [Azure DevOps proposal](https://github.com/elsa-workflows/elsa-extensions/pull/199)
- [ ] **Generated activities and plugin installation.** Turn external OpenAPI operations into typed Studio activities. Explore the same approach for Azure Functions and registered methods. Build on existing package metadata and module loading to make extensions discoverable and installable. [OpenAPI activity provider](https://github.com/elsa-workflows/elsa-core/issues/6360) · [Azure Functions](https://github.com/elsa-workflows/elsa-core/issues/3583) · [Plugin installation](https://github.com/elsa-workflows/elsa-core/issues/7310)
- [ ] **Data movement and automation.** Improve typed SQL authoring and explore reusable data pipeline and streaming primitives. [Data pipelines](https://github.com/elsa-workflows/elsa-core/issues/4809)

### Observability and operations

- [x] **Diagnostics and dashboard.** Structured and console logs, durable structured log storage, OpenTelemetry ingestion, and Studio diagnostics are available. The operational dashboard has per-section permissions from 3.9. [OpenTelemetry guide](https://github.com/elsa-workflows/elsa-core/blob/main/core/docs/wiki/opentelemetry-workflows.md) · [Dashboard permissions](https://github.com/elsa-workflows/elsa-core/releases/tag/3.9.0)
- [~] **Workflow telemetry and incident investigation.** Improve default workflow metrics, queue visibility, and links between workflow and activity logs, traces, child runs, retries, and recovery actions. The goal is for operators to see what is stuck and act on it from Studio or their telemetry stack. [Default workflow metrics](https://github.com/elsa-workflows/elsa-core/issues/5988) · [Dispatch queue discussion](https://github.com/elsa-workflows/elsa-core/discussions/8551)
- [ ] **Workflow deployment platform.** The draft proposal covers declarative environment manifests, immutable workflow artifacts, dry-run validation, and deployment history. [Deployment platform proposal](https://github.com/elsa-workflows/elsa-core/issues/7469)

### Security, identity, and enterprise readiness

- [x] **Identity and permissions.** Elsa has OIDC and external SSO options, permission-based API and Studio access, and user and role administration. 3.9 shipped the resource-based permission model and sign-out revocation. 3.10 adds tenant-scoped roles and further access and secrets hardening. [3.9 release](https://github.com/elsa-workflows/elsa-core/releases/tag/3.9.0) · [3.10.1 release](https://github.com/elsa-workflows/elsa-core/releases/tag/3.10.1) · [3.10.2 release](https://github.com/elsa-workflows/elsa-core/releases/tag/3.10.2)
- [~] **Hosted multitenancy.** Main adds opt-in fail-closed tenant resolution, registry-based tenant lookup, and parallel tenant activation. Cross-node refresh, quotas, tenant-aware trigger semantics, and parity for shared-record writes across stores remain tracked. [3.11 multitenancy](https://github.com/elsa-workflows/elsa-core/issues/9232) · [Tenant resolution](https://github.com/elsa-workflows/elsa-core/pull/9226) · [Shared-record provider parity](https://github.com/elsa-workflows/elsa-core/issues/9303)
- [~] **Production hosting and governance.** Expand tested recipes for SSO, reverse proxies, migrations, backup and recovery, and secrets rotation. Improve tenant- and role-based activity visibility, branding, localization, and embedding guidance. [Hosting and images](https://github.com/elsa-workflows/elsa-core/tree/main/apps) · [Tenant selection guidance](https://github.com/elsa-workflows/elsa-core/issues/9216) · [3.10.2 upgrade notes](https://github.com/elsa-workflows/elsa-core/releases/tag/3.10.2)

### AI-assisted workflow engineering

- [~] **Weaver Copilot.** The server and Blazor workspace are available. Continue with proposals that can be inspected, validated, and applied as visible workflow changes, with permission-aware tools and test scaffolding. [Weaver server foundation](https://github.com/elsa-workflows/elsa-core/pull/7523) · [Weaver Studio foundation](https://github.com/elsa-workflows/elsa-studio/pull/900) · [Workflow generation discussion](https://github.com/elsa-workflows/elsa-core/discussions/7367)
- [~] **Agents and tooling.** Extensions support OpenAI, Azure OpenAI, and custom providers. Broader provider coverage, tool approvals and audit, and an MCP surface for workflow inspection and validation are follow-on work. The Agent Framework migration is a proposal. [Agents](https://github.com/elsa-workflows/elsa-core/tree/main/extensions/src/agents) · [Agent Framework proposal](https://github.com/elsa-workflows/elsa-core/issues/8883)

## Suggested sequencing

1. Finish 3.11 qualification, upgrade guidance, and React Studio Preview delivery. Keep maintenance updates visible for users already running Elsa.
2. Prioritize the paths teams rely on to adopt Elsa in production. These include tenant isolation at scale, reliable dispatch and recovery, and the ability to author, run, and diagnose workflows in Studio.
3. Advance scoped improvements against those foundations. Track Wolverine as a concrete dispatcher option. Continue BPMN authoring and conformance, human-task authoring, and the first durable compensation journey through their linked work.
4. Use connector pilots, deployment use cases, and Weaver proposal review to validate broader platform work before expanding its scope.

## Follow the work

Follow the [release list](https://github.com/elsa-workflows/elsa-core/releases) for published versions, the linked issues and milestones for specific delivery work, and [#3232](https://github.com/elsa-workflows/elsa-core/issues/3232) for roadmap feedback. When suggesting a change, include the workflow you want to build or the operational problem you need to solve.
