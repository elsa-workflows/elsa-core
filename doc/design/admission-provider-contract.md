# Durable admission provider contract

Task #8658 implements the isolated-host design in [the reviewed checkpoint](https://github.com/elsa-workflows/elsa-core/issues/8229#issuecomment-6049219598). This file freezes the initial transactional store contract for parallel provider implementation; it is not runtime acceptance.

`Elsa.Workflows.Admission/IAdmissionStore.cs` defines named transactional operations. Revisions are monotonically incremented for every mutation. A null CAS result means a definite predicate miss. Exceptions, especially commit uncertainty, must propagate; no readback/retry can turn an uncertain permit into an invocable capability. PostgreSQL unique/serialization conflicts may be classified as definite contention only when the transaction is known not committed. Never automatically replay a transaction after a potentially completed commit.

Provision inserts an inactive subscription or verifies exact configuration. Retired identities cannot reset. Inactive reconfiguration retains tenant/environment/installation/subscription identity and activation boundary, invalidates bootstrap verification, and preserves dedup identity and counters. Activation requires validated policy, verified bootstrap and no retirement/reconciliation, and increments an ActivationEpoch distinct from ordinary revisions. Each admitted record binds that epoch; creation/preparation/authorization require the current active epoch. Withdraw/reactivate cannot silently revive stale records. Withdrawal linearizes against creation/preparation/authorization in the same ledger transaction. Already committed authority may still run.

Admission validates configuration, installation/channel, human/loop filters, bounded nonempty event identity and payload, trusted event time (including fresh activation, maximum age/skew and explicit late/invalid disposition), then checks unique identity and both counters atomically. Each record retains immutable AdmittedConfigurationJson and PayloadFingerprint. Runtime uses this admitted snapshot, and start operations also compare current epoch/configuration. Duplicates require original scope, occurrence time and payload fingerprint even after raw payload cleanup, and preserve known state; they do not reserve capacity again. Identity is SHA-256 of the ordered tenant/environment/installation/subscription/provider-event tuple. Independent subscriptions intentionally fan out.

Creation allocates a globally unique workflow instance ID in the same CAS before the real insert-only workflow creation/notification operation. CompleteCreation is permitted only from Creating. PrepareStart permits initial Materialized with null checkpoint/bookmark, or ExecutionObserved with exact stored checkpoint and an existing unconsumed bookmark. It requires active exact configuration and no outstanding owner. AuthorizeStart requires exact StartPreparing revision/attempt, records AuthorityOutstanding and consumes prior checkpoint/bookmark lineage. Only its definite first commit can cause the private process-local coordinator to mint a capability.

CompleteExecution requires exact StartAuthorized revision/attempt. It clears outstanding authority and records checkpoint/bookmark lineage only after actual final writes and complete operation unwind. A truly durably Finished workflow becomes Terminal/Completed with TerminalAt and releases active capacity once; suspension remains ExecutionObserved. Genuine uncertainty becomes RecoveryRequired and retains outstanding authority/capacity. Resolve must never infer safety from lease expiry. SuppressedBeforeStart requires no issued authority and no unknown creation; Resolved requires explicit audited all-owner quiescence and a separate noUnknownEffects attestation. The orchestration checks its actual local registry/durable runtime and records operator responsibility; booleans alone do not prove remote or unknown effects. Persist its AuditReference (sanitized code/reference, never arbitrary exception text) and terminal time. Completed is not an operator shortcut.

RetainedRecordCapacity counts every ledger record, including owned tombstones. Terminality releases active capacity once. Cleanup uses exact terminal revision, explicit cleanup authority and TerminalAt clock: erase payload at PayloadRetention, event identity at IdentityHorizon. An owned record remains charged against retained-record capacity after erasure; do not delete its ownership or silently free its charge. Only a terminal record with no allocated instance/authority may be deleted and release retained capacity. All duplicate/admission/cleanup/counter changes share transaction/CAS predicates; counters cannot go negative or release twice. Recovery scans must be bounded/indexed.

The selected EF definition bootstrap store must reuse the exact Management WorkflowDefinitionState shadow Data codec and UsableAsActivity value. DbSet.Add alone loses ignored Options/Variables/Inputs/Outputs/Outcomes/CustomProperties. Extract the codec shared with EFCoreWorkflowDefinitionStore rather than maintaining a second serialization implementation. Enforce actual primary ID and logical DefinitionId/version uniqueness, tenant identity and full fingerprint; reject any conflicting logical-definition rows before publication can retract them. Insert-if-absent is atomic and returns Inserted versus ExistingMatch. AcquireExclusiveAsync holds selected-provider session locks across insert/publication/ledger verification; lock identity must serialize different subscriptions targeting the same logical definition as well as competing calls for one subscription. ExistingMatch without previously verified ledger stays inactive/recovery and never republishes. Reload through the normal definition store and verify all pinned state. Normal publication/indexing is a separate audited uncertainty boundary; a partial/crashed/unknown insertion or publication remains inactive and cannot be accepted or replay notifications automatically. Repeat verified bootstrap verifies content rather than republishing.
